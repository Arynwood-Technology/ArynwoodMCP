Installation guide

Get ready for the Linux alpha.

The alpha is intended for people comfortable installing desktop software and local AI services. We would rather be clear now than create a frustrating first hour.

What you will need

  • Operating system: a supported 64-bit Linux distribution.
  • Storage: room for the app, local models, and creative assets. Models and media can be large.
  • Model service: Ollama or a compatible configured model endpoint.
  • GPU: strongly recommended for many local models and media-generation workflows.
  • Internet: needed for initial downloads and any external service you explicitly connect.

Install in four steps

  1. Download: Choose the AppImage or Debian package from the official release page.
  2. Verify: Compare the package SHA-256 checksum with the value published in the release notes.
  3. Install: Follow the package-specific instructions supplied with the release.
  4. Launch: Complete the environment check, connect a model service, and begin with the starter project.

Alpha note: Release packages, supported distributions, and exact requirements must be confirmed on the official release page. Do not download builds from unofficial sources.

Knowledge and projects

Keep the useful context. Leave the clutter behind.

Instead of repeating the same background in every chat, organize approved source material so the work starts from a better foundation.

Good first sources

  • A project brief or creative outline.
  • Brand voice notes and approved examples.
  • Research you have permission to use.
  • Client requirements and internal checklists.
  • Meeting notes or a prior draft that needs revision.

Good knowledge habits

  • Add only what is relevant to the task.
  • Review material for privacy, permissions, and accuracy first.
  • Use clear source names so you can trace where an idea came from.
  • Treat AI output as a draft to review, not an authority.
  • Remove or update stale material when a project changes.

Privacy and control

Local-first means you should know what is happening.

Your ideas, drafts, media, and credentials deserve clear boundaries. Arynwood’s design goal is to make those boundaries visible and configurable.

What stays under your control

Local project data, configured local model services, and local creative workflows can remain on hardware you manage. You decide what to add to a project and which local tools to connect.

What can connect outward

Search, publishing platforms, model endpoints, OAuth-connected accounts, update checks, and other optional services can involve a network connection. Review configuration, permissions, and each consequential action.

Good security starts with good habits.

Use strong passwords on your computer, keep the operating system and Arynwood updated, never share API keys, and use only official releases. Do not add private client material until you understand your local setup and organization’s policies.

Frequently asked questions

Clear answers before you download.

What is Arynwood MCP?

Arynwood MCP is a local-first AI creative studio. It brings AI chat, project knowledge, creative-tool integrations, automation, and publishing preparation into one desktop workspace.

Who should try the alpha?

The first Linux alpha is best for creators, builders, and small teams comfortable with local AI setup who can give practical feedback. It is not yet presented as a universally supported consumer application.

Do I need a GPU?

A GPU is strongly recommended for many local models and for image, audio, video, and music workflows. Exact performance depends on the model, service, drivers, GPU memory, and the task. Check the official release requirements before installing.

Do I need Ollama?

The primary local-model path uses Ollama. Arynwood can also be configured around compatible model endpoints. The official release documentation should list the currently tested choices.

Is my work private?

Arynwood is designed local-first, which can keep data and models on hardware you control. Some optional features may contact external services you configure, such as web search or connected publishing accounts. Review configuration and permissions for your own needs.

Can I publish directly to social media?

Supported social integrations can prepare and publish through accounts you connect using your own credentials. Always review content, audience, timing, and platform permissions before publishing.

Where do I get help or report a problem?

Use the official release page and support channel once announced. A useful report includes the app version, Linux distribution, hardware/model service, exact steps, relevant logs, and screenshots with any credentials removed.
