# Arynwood MCP 0.4.7: One program for every computer

**Status: release candidate, in hands-on testing.** Not published yet.

The same app now runs well on a computer without an NVIDIA GPU, such as a rented desktop
server. Nothing is removed or hidden on those computers. Features that need an NVIDIA GPU are
marked and switched off, and an **endpoint** on another computer can do what this one can't:
chat, and image generation in Design Center.

**If you run 0.4.6, update.** 0.4.6 sent Arynwood's instructions to Hermes 3 only on replies
without tools, which is most replies, so the model often answered without its persona,
memories, Agent Config notes or the rule to treat web and tool content as data. See the
first item under Fixes.

## What's new

- **CPU mode,** in Tools: Auto, On or Off. Auto turns it on when no NVIDIA GPU is found. Tools
  that need one show an NVIDIA GPU tag and can't be started, and the backend refuses them too.
  Music and Video Studio keep their CPU features and mark the GPU ones. Chat on the computer's
  own CPU uses a 6144-token context, keeps its model loaded for an hour, loads it when the app
  opens, and says when the CPU is working.
- **Endpoints for chat.** On the Servers page, **Use for chat** picks the server chat runs on,
  and the choice is remembered across launches. Any Ollama or OpenAI-compatible server works,
  and an OpenAI-compatible one can carry its own chat model.
- **Endpoints for images.** **Use for images** sends Design Center's AI Gen to any
  OpenAI-compatible images API instead of local Stable Diffusion, for text-to-image and
  image-to-image.
- **Presets for installers.** A host that installs Arynwood for its customers can set the
  endpoint and CPU mode in the backend's `.env`.

Guide, with what an endpoint receives: [docs/endpoints.md](../endpoints.md). CPU mode:
[supported platforms](../supported-platforms.md#cpu-mode).

## Fixes

- **Arynwood keeps its instructions when tools are attached.** Ollama's `hermes3` template
  leaves the system prompt out whenever tools are attached. Arynwood now detects a template
  like that and sends the instructions as the first message. The Kdenlive tool loop had the
  same problem and is fixed by the same change.
- **The background service exits with the app.** A crashed or killed app no longer leaves the
  backend holding port 8010, so you don't have to run `pkill -f arynwood-backend` before
  starting again.
- **The Servers page no longer receives saved tokens.** It shows only whether a token is set.

## Also in this release

- Trained LoRAs start at weight 0.6 in Design Center instead of 1.0, and a LoRA without a
  recorded checkpoint is generated on the checkpoint its own file names.
- The Chatterbox voice library starts empty. The preset voices were Tortoise TTS's samples,
  many cloned from real people. Add your own voice, or one you have permission to use.
  Voices you've saved stay on your machine.

## Known issues

- **Local chat on a CPU is slow.** On a 4 vCPU server, a reply takes several minutes. Use an
  endpoint for everyday chat there, or a computer with more cores.
- **Small local models are unreliable at editing clips by name** (unchanged since 0.4.6).
  Every delete still asks first; read the approval card before you approve.
- Instructions now reach Hermes 3 on every reply, so its prompt is longer: about 2,700 tokens
  instead of about 750. Replies are better grounded, and the first one after a model load
  takes a little longer, most noticeably on a CPU.
