# Arynwood MCP 0.4.6: Security fixes and Hermes 3

**Status: built, waiting to be published.** The GitHub release is a draft with every package
attached. Plan and release checks: [docs/scope.md](../scope.md).

**If you run 0.4.5, update.** 0.4.5 has two holes that this release closes:

- **Web pages could read the local API.** 0.4.5 accepted requests carrying a `null` browser
  origin, which sandboxed iframes and local `file://` pages send. While the app was running,
  any website could read your conversations and memories from `localhost:8010`. Foreign and
  opaque origins are now refused before any route runs, and an exact Host check blocks DNS
  rebinding.
- **A web page could start a tool install.** Installs ran on a plain `GET`, so loading a link
  or an image could start one. They now need a POST.

Built by CI from commit `d58a553` (tag `v0.4.6`), by the `Release (Linux)` and `Windows desktop`
workflows.

**New default model: run `ollama pull hermes3:8b` after updating.** The bundled personas and
the tool-calling agent now use Hermes 3 8B. It was picked by a
[benchmark of eight models](https://github.com/Arynwood-Technology/local-ai-benchmarks/blob/main/TOOL-CALLING.md) on an RTX 3060 12 GB: the same tool
decisions as the previous model, no instructions followed from planted text, and 2.5 times as
fast in about 5 GB less memory. Your own personas keep the models you set.

## Also in this release

- **Safer network features:**
  - learning from a URL reaches public addresses only, within size and time limits;
  - deploys require a known SSH host key;
  - the launcher no longer starts unattended YouTube publishing by default.
- **One approval policy for tool calls.** An approval covers only the exact call it was given
  for, once, and expires. Unreviewed MCP servers need approval for every call.
- **Fixes:**
  - Stable Diffusion recovers when A1111 stalls while unloading a model;
  - LoRAs generate on the checkpoint they were trained on;
  - the Tool Library lists only integrated tools;
  - fonts are served by the app, with no Google Fonts requests;
  - conversation and writer tuning.
- **Experimental, off by default: the headless gateway.** An owner-only remote control for
  your workspace, run from a source checkout. The desktop packages don't start it. See
  [docs/gateway.md](../gateway.md).

## Known issues

- **Small local models are unreliable at editing clips by name.** Hermes 3 sometimes picks the
  wrong clip id, or the wrong tool (a marker tool for "the blue clip"). Every delete still asks
  first, and the approval card shows the tool and its arguments. Read it before you approve.
- **Update mcp-kdenlive too.** Cutroom crashed when a delete was given an id that isn't on the
  timeline. mcp-kdenlive now checks the id first (commit `bc52f76`); restart the
  `mcp-kdenlive` service after updating it. The editor itself still needs a fix for other tools
  that take a clip id.
- If the desktop app is killed or crashes instead of being closed normally, its background service
keeps running and holds port 8010, and the next launch reuses it. Closing the window shuts both
down. After a crash, run `pkill -f arynwood-backend` before starting the app again. (Unchanged
since 0.4.5; a fix needs the desktop shell to tie the service to its own lifetime.)
