# 0.5.5 release-readiness record

Status: **release candidate**. Publication requires green checks on the release commit, the
hands-on checks below on a packaged candidate, verification of the tagged Linux and Windows
artifacts, and owner signing.

Release prep: `release-prep/0.5.5`.

## What changed since 0.5.4 that only a packaged build can show

- **Tauri 2.12.5 and shell plugin 2.6.0** (#32). The shell plugin no longer uses `signal-hook` to
  watch child processes. The backend sidecar is a child of the app, so starting it and stopping
  it on quit has to be checked in a real AppImage. CI compiles the Windows shell; the Linux shell
  was compiled in an Ubuntu 24.04 container but not run.
- **Vite 8, TypeScript 6.0, ESLint 10** (#48). The frontend bundle is produced by a new bundler
  and runs in WebKitGTK only in the packaged app.
- **Community without the wish lamp** (#47).

The app's database schema is unchanged since 0.5.4 (`backend/db.py`), so going back to 0.5.4
after testing is safe.

### Finding: the AppImage stopped choosing X11

Under Xvfb the first candidate's window stayed white while 0.5.4, run the same way, drew the
Dashboard. The frontend wasn't the cause: the same 0.5.5 `dist/` rendered in WebKitGTK 2.50.4 (the
version both AppImages bundle, in an Ubuntu 22.04 container) and 2.52.6. The difference was the
bundler's GTK launch hook, which came with the Tauri CLI update (#46):

- 0.5.4's hook: `export GDK_BACKEND=x11 # Crash with Wayland backend on Wayland`
  (tauri-apps/tauri#8541). The 0.5.5 candidate's hook: that line commented out, "Monitor this
  closely. AppImage used to crash on Wayland!"
- It also sets `GIO_MODULE_DIR` to the bundle's GIO modules instead of `GIO_EXTRA_MODULES`, bundles
  `libproxy`, and no longer bundles `libwayland-client`. The bundled modules include `libgiognutls.so`.

On a Wayland desktop the candidate therefore ran on GTK's Wayland backend; no release had. With
`GDK_BACKEND=x11` it rendered exactly like 0.5.4 (backend connected, models listed). `main.rs` now
sets `GDK_BACKEND=x11` for an AppImage when the user hasn't set one, as every release up to 0.5.4
behaved; the `.deb` keeps the system default. `tests/test_appimage_display_backend.py` covers it.
The second candidate is built from that commit.
