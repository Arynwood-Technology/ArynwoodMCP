# Arynwood MCP 0.5.0: Community on a server, readable everywhere

**Status: release candidate.** Packages are built by the tagged release workflows.

Anyone on 0.4.8 or 0.4.9 sees the update notice once this is published; earlier versions need
one manual install.

## What's new

**Community with a Grove on a server works.** A Grove behind Cloudflare or nginx, such as
community.arynwood.com, compresses its answers. In 0.4.9 Arynwood's backend passed them to the
Community page still compressed, so the page couldn't read them. It now unpacks them first,
counts the size limit against the unpacked size, and asks for live change notices
uncompressed. A Grove on this computer was never affected.

The relay for the host's IRC and peer-message sockets now always closes the Grove's side, even
when it is interrupted while closing (a test caught this about one run in five; 0 in 30 now).

**Readable everywhere.** An automated contrast check of every page and a scan of every
hard-coded colour found text below the 4.5:1 standard. All of it now passes:

- In Chat, your own messages use the darker green (1.78:1 before, 5.98:1 now).
- Start Ollama, Saved, delete and recording buttons have darker fills behind their white text
  (`success-solid` and `danger-solid`, alongside 0.4.9's `accent-solid`).
- Purple left over from the old look is now green-teal where it stands for Arynwood, or a
  lighter violet where it marks a category. Grey "stopped" labels are lighter.

**Community screens from Arynwood Grove 0.4.1**, including its readable avatar colours.

## Security updates

- Python: `urllib3` 2.8 and `h2` 4.4.1 are now required (PYSEC-2026-4175, -4176, -4177 and
  PYSEC-2026-3628). Both come in through other packages (`requests`, and `ddgs`'s HTTP/2
  support).
- Frontend: packages updated within their versions (React 19.3, React Router 7.18.4, Vite
  7.3.7, Vitest 5.0.3 and others), including the `source-map-js` fix (GHSA-68fv-2mgg-jv7q).
  Tauri stays at 2.10.
- Rust: `anyhow`, `event-listener` and `quick-xml` updated (RUSTSEC-2026-0190, -0221, -0194,
  -0195). `quick-xml` is only built for macOS, which Arynwood doesn't ship.
- npm audit, pip-audit and cargo audit report no known vulnerabilities. cargo audit still lists
  unmaintained or unsound warnings for crates that come with Tauri 2.10's Linux toolkit
  (GTK 0.18 bindings and others); they change only with a Tauri upgrade.

## Validation

- Backend: 765 passed; 39 live evaluation tests excluded. New: relay tests against a stand-in
  Grove that compresses like Cloudflare (decoded answers, the size limit on the unpacked size,
  live notices requested uncompressed), which fail on 0.4.9's relay. The host-socket tests
  passed 30 runs in a row.
- Frontend: 162 passed. Lint: 40 problems, now the tracked baseline (was 41). Production and
  demo builds passed (existing chunk-size warning).
- Contrast: every page of the demo build (13 views, including Chat after a reply) checked in
  Chrome for text below 4.5:1 (3:1 for large text), with no failures left.
- **Real WebKitGTK 2.52**, with the built app served from `tauri://localhost` like the packaged
  app, against a throwaway Arynwood Grove 0.4.1 and a scratch backend: all 14 steps passed
  (create a Grove and sign in with no cookie in the web view, a second member's task arriving
  through live notices in 0.42 s, scoped styles, signed in after a backend restart, export
  saved as a file, sign-out everywhere, an invitation to another Grove asking first).
- Against community.arynwood.com through the relay (no sign-in): status and sign-in checks
  come back as readable JSON; 0.4.9 returned compressed bytes.

Not run: signing in to a server Grove from the app, IRC, Mail and NKN against live networks,
and a clean Windows machine install.
