# Arynwood MCP 0.5.5 — security and maintenance updates

Release candidate. Publication waits for the checks in `0.5.5-readiness.md` and the owner
signing the verified packages. Users of 0.5.4 should update after publication.

## Packages

- `arynwood-mcp_0.5.5_amd64.AppImage`: Linux x86_64, any distribution with glibc 2.35 or newer
- `arynwood-mcp_0.5.5_amd64.deb`: Debian, Ubuntu and derivatives
- `arynwood-mcp_0.5.5_x64-setup.exe`: Windows x64 (alpha), per-user installer
- `SHA256SUMS`: the SHA-256 checksum of every package above
- `SHA256SUMS.asc`: the release key's signature of `SHA256SUMS`
- `SHA256SUMS.txt`, `SHA256SUMS-windows.txt`: the build's own checksum lists
- `arynwood-mcp_0.5.5_provenance.intoto.jsonl`: the build attestations of the three packages (new)

## Security fixes

- **Deploy checks SSH host keys before signing in.** A deploy target whose trusted host key is
  weaker than 2048-bit RSA or 256-bit ECDSA, or is a key type Arynwood doesn't recognize, is
  refused before any credentials are sent. Ed25519 keys are accepted.
- **Desktop shell:** Tauri 2.12.5 with the shell (2.6.0) and notification (2.8.0) plugins. This
  removes `rand` 0.7.3, which had no fixed release for RUSTSEC-2026-0097, and the
  unmaintained `fxhash` (RUSTSEC-2025-0057) from the build. The only `rand` left is 0.10.3.
- **Python:** certifi 2026.10.23 (a current trust bundle) and setuptools 84.2.1, with FastAPI
  0.162.0, jsonschema 4.26.0, pytest 9.2.0 and PyInstaller 6.22.3. Both hashed dependency locks
  were regenerated, and CI now checks that each lock matches its inputs.
- **Frontend:** dependency updates, including the Tauri CLI and Vitest fixes.

## Removed

- Community's genie lamp and **Make a wish** form, with the admin wishes panel and the wish
  relay paths. Wishes already on a Grove are left there; Grove itself keeps the feature.

## Verifying downloads

Every package's build attestation now also comes as a release file,
`arynwood-mcp_0.5.5_provenance.intoto.jsonl`. With it beside a download, add
`--bundle arynwood-mcp_0.5.5_provenance.intoto.jsonl` to `gh attestation verify` to check the
package against the release's own copy instead of fetching it from GitHub.

## Build and tooling

- The frontend builds with Vite 8, ESLint 10 and TypeScript 6.0, and uses lucide-react 1.x.
- CI and release workflows use the current major versions of GitHub's checkout, artifact and
  Pages actions.

## Dependency advisories still open

These come from upstream projects and have no compatible fix yet:

- `glib` 0.18.5 (RUSTSEC-2024-0429), required by Tauri's Linux WebKitGTK stack.
- Unmaintained crates: `proc-macro-error` (RUSTSEC-2024-0370), from the same stack, and `zvariant`,
  `zbus_names` and `zvariant_derive` (RUSTSEC-2026-0370, -0371, -0372), required by the notification
  plugin through zbus 5.
- `minimatch` (GHSA-g3hv-75wg-m249), in the ESLint development tools only; it isn't in the app.

## Verify your download

Release key fingerprint: `C536 F3C4 689A 1734 920A  0E5B F1F8 0C83 C593 8FF0`
Public key: <https://github.com/Arynwood-Technology/ArynwoodMCP/blob/main/docs/release-signing-key.asc>

Put `SHA256SUMS`, `SHA256SUMS.asc` and the package in one folder, import the public key, then:

```bash
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
```

The first must report `Good signature` from the fingerprint above; the second `OK` for your package. Or run
[`scripts/verify-release.sh`](https://github.com/Arynwood-Technology/ArynwoodMCP/blob/main/scripts/verify-release.sh),
which does both. Windows steps and what to do if a check fails:
[release signing](https://github.com/Arynwood-Technology/ArynwoodMCP/blob/main/docs/release-signing.md#verifying-a-download).

Each package also has a build attestation:
`gh attestation verify <package> -R Arynwood-Technology/ArynwoodMCP`. Add
`--bundle arynwood-mcp_0.5.5_provenance.intoto.jsonl` to check it against this release's copy.
