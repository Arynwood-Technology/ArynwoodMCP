# Arynwood MCP 0.5.3: security fixes

**Status: release candidate.** Not tagged yet.

0.5.3 is a security release with no new features. Anyone on 0.4.8 or later sees the update
notice; earlier versions need one manual install.

## What's new

**Pillow 13.0.0** (was 12.3.0). Pillow opens every picture Arynwood handles. 12.3.0 has 35
published advisories, including buffer overflows, use-after-free and decompression-bomb bypasses
in its image decoders.

**A picture uploaded for a social post is only ever a picture.** Until now, the uploaded file's
own name chose the saved extension. A web page uploaded as the "picture" was then served as a web
page (`text/html`) from Arynwood's own address, and the extension wasn't checked for path
characters. Now:

- **Uploads are re-saved as real pictures:** each upload is opened and saved again as JPEG, PNG
  or WebP, under a name the backend chooses. Camera and location data are dropped.
- **Only pictures are served:** both addresses that serve uploads, `/social-media/` and
  `/api/social/media/`, send only pictures, with `nosniff` and a sandboxing policy.
- **Earlier uploads:** they keep working when they are JPEG, PNG, WebP or GIF files. Any other
  kind is no longer served.

**Builds run on Node.js 22.23.4,** the October 21 security release. Three of the workflows used
Node 20, which no longer gets security fixes. The desktop app doesn't include Node, so this changes
only how it is built.

**A source checkout needs Python 3.11 or newer,** because Pillow 13 does. Python 3.10 reaches its
end of life this month. CI tests on 3.11, and the Linux release is now built on 3.12, as the
Windows release already was. If your checkout's `venv` is on 3.10, make it again with a newer
Python and reinstall `requirements.txt`.
