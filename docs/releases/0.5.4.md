# Arynwood MCP 0.5.4 — draft release notes

Draft only. This release has not been created. Users of 0.5.3 do not yet have
these October 24 fixes. Update when the owner publishes the reviewed release.

## Security fixes

- Music downloads now accept only jamendo.com and its subdomains. Lookalike
  domains can no longer pass the music proxy address check.
- Community IRC treats unusual channel and nickname strings as ordinary names,
  preventing them from interfering with JavaScript object properties. NickServ
  passwords are no longer saved in browser local storage; older saved copies
  are removed. You may need to enter the password again.
- Social sign-in accepts completion messages only from the sign-in popup opened
  by that page, preventing unrelated windows from claiming sign-in completed.
- Backend responses include browser protections against content-type guessing,
  referrer disclosure, and unwanted framing. Design Center and Community
  previews retain their specific framing policies.
- WebSocket API keys are redacted from backend access and connection logs.
- On Unix, the database and its companion files are restricted to their owner,
  and the default data folder is private. Custom parent-folder permissions are
  left alone. This Unix permission change does not apply on Windows.
- Studio and Music Lab stop in-memory uploads above 512 MB. Voice model imports
  stream to disk with a 1 GB limit, remove partial oversized imports, and accept
  only plain model names. Oversized uploads now return a clear refusal.
- Python dependencies were updated: FastAPI 0.157, uvicorn 0.54,
  python-dotenv 1.2.4, ollama 0.6.3, and ddgs 9.16. These updates are not presented
  as CVE fixes without verified advisory evidence.

- Build automation now defaults to read-only repository access and grants write
  access only to the jobs that need it. Its external build actions are pinned to
  specific revisions, reducing unexpected changes in the release pipeline.

## Desktop browser policy

The packaged app permits scripts only from its own bundled frontend. Inline
scripts and JavaScript eval are blocked. Connections are limited to the local
backend, Tauri communication, and GitHub's API for update checks. Images can
still load from HTTPS addresses, including Community logos and avatars.
Embedded objects and outside form targets are blocked. Development mode has
its separate development policy.

Normal creative workflows are intended to keep working. Rebuilt AppImage
validation remains a release gate; see `0.5.4-readiness.md` for observed results.
This draft must not be published yet: the local rebuilt AppImage still fails
microphone recording and the broader media helper, despite zero observed CSP
violations during the tested interactions.

## API description

`/docs` and `/redoc` have been removed because their interactive documentation
loaded third-party scripts onto the trusted backend origin. The machine-readable
API description remains at `/openapi.json`, usable with an OpenAPI viewer you
choose. The separate API reference documentation work must be linked and checked
by the owner before publication; it is not included or claimed complete here.

## Desktop dependencies

The Rust Tauri crate and npm `@tauri-apps/api` are pinned together at 2.12.4.
Dependabot #10 proposes Rust 2.12.5, but no matching npm API 2.12.5 was published
when checked. Version 2.12.4 is the nearest exact published pair. Building from
source now requires Rust 1.90 or newer.

The Linux media bundle now also requires GStreamer’s `interleave` plugin. It
provides `deinterleave`, needed for Music Lab’s WebAudio audition and microphone
source paths; simple playback and oscillator-only recording did not reveal its
absence. A new `webaudio:` media check covers delayed playback errors.
