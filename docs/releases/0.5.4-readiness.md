## Additional media packaging dependency

The first rebuilt AppImage omitted `libgstinterleave.so`, which provides
`deinterleave`. Music Lab's MediaElementAudioSourceNode audition failed with
media error 4, "Internal data stream error," and mic Stop never reached review.
GStreamer diagnostics explicitly reported `deinterleave` missing. Neither
failure emitted a CSP violation. Simple playback and oscillator-only recording
in the previous helper passed despite this gap.

`scripts/stage_gstreamer_plugins.sh` now requires `interleave` (43 staged plugins,
previously 42). This is a media packaging fix, not a CSP or version-check change.
`scripts/check_webkit_media.py` adds `webaudio:FILE`, which waits four seconds
through the WebAudio source path. Against the original extracted AppImage it
fails as expected with currentTime 0 and mediaError 4. Rebuilt-artifact results
are recorded below. The plugin fix clears WebAudio playback, but does not clear
the separate recorder stream-profile failure.

### Remaining media gate

After fixing `deinterleave`, the mic still fails on this Ubuntu 24.04 build.
This reproduces with the PulseAudio null microphone, trusted WebDriver pointer
clicks, and a synthetic tone supplied to that source; it is not cleared by moving
the audio socket into the standard runtime directory. Passive observers saw a
running AudioContext, an inactive recorder after Stop, a zero-byte `dataavailable`
event, and a `stop` event. The application remains outside recording review.

GStreamer reports `Couldn't find a compatible stream profile`, then capture
`streaming stopped, reason not-linked (-1)`, and `EOS hasn't reached the sink`
after waiting. It also reports a fallback from missing `isofmp4mux` to `mp4mux`;
that fallback alone is **not established as the cause**, and no codec dependency
has been guessed or added to hide the failure.

The final exact-bundle media helper command was:
`check_webkit_media.py MEDIA_DIR audio:tone.wav webaudio:tone.wav recorder`.
It returned failure overall:

- `audio:tone.wav`: `ok: false`, currentTime 0 at the existing 700 ms snapshot,
  readyState 4, no media error. The app's longer audition check above does complete.
- `webaudio:tone.wav`: **passed**, currentTime 4.78, readyState 4, no media error.
- `recorder`: `ok: false`, zero recorded bytes.

The earlier simple helper run had passed audio and oscillator recording, so that
success is not substituted for these final failing results. No failing case was
skipped. The microphone and overall media gate must be resolved and rerun on a
supported throwaway build before release; this record does not claim release readiness.
A connected Community check also needs a disposable Grove service; none was supplied
or installed in this MCP-only session. The separate API reference work was not imported.
CVE naming remains for the owner's confirmation in `0.5.4.md`.

Local raw evidence and helpers are under `/tmp/arynwood-readiness-logs/` and
`/tmp/arynwood-*.py`; the final artifact is in this worktree's
`frontend/src-tauri/target/release/bundle/appimage/`. These test files are not
release artifacts and were not uploaded.
